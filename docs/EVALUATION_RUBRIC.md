# 阵容分析输出评分标准

状态：Evaluation Rubric v1.0（Accepted）  
最后更新：2026-08-21

## 1. 评分对象与解释边界

本标准评判的是：**模型针对给定阵容、任务边界和可用版本知识生成的一条战术分析回答**。
它不是普通文笔评分，也不能直接读取模型内部能力。只有在多个独立样本上汇总后，才能
把输出表现作为模型能力的间接证据。

评分必须同时查看：

- 原始阵容与场景输入。
- 模型完整输出。
- 实验指定的 ruleset 和知识上下文。EXP-0001 的评估目标是 Data Dragon 16.16.1
  及截至 2026-08-21 的官方修正；没有该 ruleset 的可靠依据或确有版本争议时，按本
  标准的 `NA` 规则处理。

本标准可用于 baseline 输出、教师模型候选和专家编写的任务答案。原始视频转写、文章
或比赛解说不是任务答案，必须先转化为可评估的 `INTERACTION`、`FULL`、`CF` 或
`REPAIR` 样本。

## 2. 通用计分方法

每个一级维度包含 5 个检查项。每项只能记：

- `1`：正确、充分，并有当前阵容或给定知识支持。
- `0.5`：方向基本正确，但覆盖不完整、条件缺失或表达含糊，不构成严重误导。
- `0`：缺失、明显错误、前后矛盾，或无法由输入与给定知识支持。
- `NA`：当前输入或版本条件下确实无法裁定；不能用 `NA` 回避本应回答的内容。

维度分数计算：

```text
dimension_score = 已得检查项分数之和 / 可评检查项数量 × 5
```

结果保留两位小数。每个 `0`、`0.5` 和 `NA` 都必须记录：检查项、模型原文证据、解释、
二级诊断标签、严重度和审核者置信度。API、解析或样本关联失败属于 `evaluation_error`，
不伪造成 0 分，也不进入均值。

## 3. E1：输入与输出契约

E1 是质量门槛，优先由程序全量检查，实体、阵营和任务边界再由 Judge 或人工审核补充。

| 检查项 | 1 分 | 0.5 分 | 0 分 |
|---|---|---|---|
| E1.1 JSON 合法 | 原始要求范围内可直接解析为单个 JSON 对象 | 仅有不影响提取的轻微包裹文本，但违反纯 JSON 要求 | 无法可靠解析 |
| E1.2 Schema 完整 | 字段、类型、必填分支和叶子全部合法 | 只有非关键协议瑕疵，且仍可稳定解析 | 缺关键字段、类型错误或存在未声明结构 |
| E1.3 阵营与英雄一致 | 十名英雄归属全程正确 | 一处孤立指代含糊，未影响主要结论 | 串边、张冠李戴或遗漏关键英雄 |
| E1.4 位置理解 | 四个分路及打野/辅助关系正确 | 一处次要位置表述不清 | 关键分路或职责对象混淆 |
| E1.5 任务边界 | 不编造装备、经济、选手风格或实时状态，不把优势写成必胜 | 有轻微越界措辞但未参与结论 | 依赖输入不存在的动态信息形成主要结论 |

封顶规则：

- 输出无法解析为 JSON 时，`E1 = 0`。
- JSON 可解析但完整 Schema 不合法时，`E1` 最高 3 分。
- E1 同时保留 JSON 合法率、Schema 合法率、实体/阵营错误率和任务越界率，不能只报告平均分。

## 4. E2：机制事实准确性

E2 在当前 closed-book baseline 中用于诊断模型原有知识缺口；未来 fixed-KB 实验还要
区分检索错误、知识忠实度错误和事实正确但推理失败。

| 检查项 | 1 分 | 0.5 分 | 0 分 |
|---|---|---|---|
| E2.1 关键事实覆盖 | 使用了支持主要结论所需的关键机制 | 覆盖部分关键机制但有明显遗漏 | 回避具体机制或遗漏决定性事实 |
| E2.2 英雄机制正确 | 技能效果、目标、限制、伤害/控制类型正确 | 有不影响结论的轻微模糊 | 存在技能幻觉、机制张冠李戴或过时效果 |
| E2.3 英雄画像正确 | 射程、清线、前排、保护、开团、持续输出等定位合理 | 大方向正确但遗漏关键职责 | 核心定位错误并影响阵容判断 |
| E2.4 游戏规则正确 | 线权、视野、地形、节奏和资源规则使用正确 | 结论合理但转换条件不足 | 使用不存在或明显不成立的系统规则 |
| E2.5 版本与不确定性 | 避免无依据精确数值，对版本敏感和非常规情况适度保留 | 声明不足或略显保守但未误导 | 对不确定事实无依据强断言，或用免责声明代替分析 |

EXP-0001 以 Data Dragon 16.16.1 及截至 2026-08-21 的官方修正为事实与规则目标。
能由该 ruleset 的可靠资料裁定的机制按该版本评分；缺少可靠依据或确有版本争议的
事实记 `NA`，不能据此扣分。完全回避机制细节时，E2.1 不能得 1 分。测试阵容的
原始创作版本未知，不把 `standard_meta` 标签解释为经过该 ruleset 专家验证的竞技结论。

封顶规则：虚构或颠倒决定性机制，并直接造成主要战术结论错误时，`E2` 最高 2 分。

## 5. E3：阵容交互推理

| 检查项 | 1 分 | 0.5 分 | 0 分 |
|---|---|---|---|
| E3.1 对线与小规模 | 用射程、推线、换血、控制和游走条件解释关键关系 | 方向合理但条件或风险不完整 | 脱离机制断言强弱或把单挑结论当团队结论 |
| E3.2 队内协同 | 说明先手、跟进、伤害、保护或拉扯链 | 识别协同但缺少次序、目标或条件 | 只罗列技能或描述错误协同 |
| E3.3 跨阵营克制 | 识别双方关键工具之间的克制与反制 | 发现主要关系但遗漏一项重要反制 | 完全忽略或颠倒决定性交互 |
| E3.4 双向与条件性 | 同时考虑双方工具、成立条件和失败风险 | 基本双向但一方明显较浅 | 把对手当作不行动或把条件性结论写成必然 |
| E3.5 战术后果 | 把交互转化为对线、团战、视野或资源影响 | 有后果判断但缺少转换链 | 交互描述与后续策略无连接或互相矛盾 |

只罗列英雄或技能、没有解释如何发生交互时，`E3` 最高 2.5 分。事实错误导致的交互
错误首先标 E2 根因，同时根据 E3 推理受损程度评分，不能重复把同一错误解释成两个
独立根因。

## 6. E4：阵容整体推演

| 检查项 | 1 分 | 0.5 分 | 0 分 |
|---|---|---|---|
| E4.1 团队画像 | 聚合双方伤害、射程、控制、前排、清线和机动结构 | 抓住主要结构但覆盖不全 | 只有逐英雄介绍或整体画像明显错误 |
| E4.2 阵容原型 | 识别主要或混合打法，并说明成立条件 | 原型大体合理但标签过于单一 | 强行误分类或原型与英雄组合冲突 |
| E4.3 优势与短板 | 同时指出擅长、害怕什么以及相应条件 | 有优势或短板，但另一面较浅 | 只宣传优点或给出不存在的结构短板 |
| E4.4 强弱期 | 由成型条件和组合关系说明相对发力期 | 时段方向合理但依据较弱 | 套模板、简单相加个人曲线或颠倒主要强弱期 |
| E4.5 线权与资源转换 | 解释先动如何转换为入侵、视野、资源、换线或推塔 | 指出转换方向但缺少到场/风险条件 | 从“有线权”直接跳到控制全部资源，或规则不成立 |

答案只有逐英雄介绍、没有团队层聚合时，`E4` 最高 2 分。核心阵容原型或主要强弱期
判断颠倒并影响全文时，`E4` 最高 2 分。

## 7. E5：制胜条件与因果

| 检查项 | 1 分 | 0.5 分 | 0 分 |
|---|---|---|---|
| E5.1 蓝方制胜条件 | 有阵容依据、具体且可执行 | 基本合理但偏泛或缺一段关键因果 | 缺失、与阵容冲突或依赖编造前提 |
| E5.2 红方制胜条件 | 有阵容依据，且不是蓝方建议的简单换名 | 基本合理但区分度不足 | 缺失、错误或只是蓝方建议换名 |
| E5.3 分阶段计划 | 对线、转线和团战期目标与避险点基本清楚 | 有阶段意识但缺少一个重要阶段 | 建议阶段错位、不可执行或彼此冲突 |
| E5.4 对手反制与调整 | 预判对方主要反制并给出条件化调整 | 提到对手但调整较浅 | 单边剧本、无视对方工具或把一种打法写成必然 |
| E5.5 因果闭环与具体性 | 策略可追溯到具体英雄、交互、强弱期和资源目标，前后一致 | 主链成立但局部泛化或证据不足 | 通用口号、无依据断言、因果跳跃或前后矛盾 |

封顶规则：

- 一方制胜条件完全缺失时，`E5` 最高 3 分。
- 双方主要只有“发育、控龙、抱团”等可替换阵容的口号时，`E5` 最高 2 分。
- 主要策略与前文机制/强弱期结论直接矛盾且无条件解释时，`E5` 最高 2 分。

## 8. 单条记录结构要求

每条成功评估至少保存：

```json
{
  "sample_id": 1,
  "rubric_version": "evaluation-rubric-v1.0",
  "dimension_scores": {
    "E1": 5.0,
    "E2": 3.75,
    "E3": 3.5,
    "E4": 3.0,
    "E5": 2.5
  },
  "criterion_results": [
    {
      "criterion_id": "E5.5",
      "score": 0.5,
      "evidence_quote": "模型原文片段",
      "explanation": "主因果链存在，但建议仍较通用",
      "capability_id": "Q02",
      "severity": "minor",
      "confidence": "high"
    }
  ],
  "evaluation_error": null
}
```

fixed-KB 开发实验已由 `kb_judge_evaluation_v1.schema.json`、`run_kb_judge.py` 和
汇总器支持此结构；正式 EXP-0001 的旧 Judge 与人工审核代码仍未统一迁移，不能把开发
实现描述成正式评估已完成。

## 9. 数据集层汇总

正式报告至少包含：

- E1～E5 的可评样本数、均值、中位数和分布。
- 每个检查项的 `1 / 0.5 / 0 / NA` 数量。
- 二级标签错误数、严重度和代表性原文证据。
- JSON、Schema、实体/阵营、任务越界等 E1 原始硬指标。
- Judge/API/解析/关联失败数及排除原因。
- 各 `scenario_type` 的分层结果；样本过少时不作强结论。

不建议只公布一个总分。若需要辅助性的语义综合分，可计算：

```text
semantic_score = E2 × 20% + E3 × 25% + E4 × 25% + E5 × 30%
```

E1 作为质量门槛单独报告，不进入语义综合分。无法进行语义评分的输出不伪造成语义
0 分，但必须计入“语义不可评率”，防止只报告成功样本造成结果虚高。

## 10. 人工盲审协议 v1.0

- 从 50 条正式输出中按 `scenario_type` 固定种子分层抽取 12 条。
- 至少两名具备 LoL 阵容分析能力的审核者独立评分，互相不可见，也不可见 Judge 分数。
- 正式审核前，用不属于冻结测试集的 3 条练习输出校准对检查项的理解；练习结果不进入实验。
- 审核者逐检查项评分并提供扣分证据，不能只给 E1～E5 总分。
- 对同一维度相差 2 分及以上的样本进行复核；保留原始评分和复核结论。
- 报告每个维度的线性加权 Cohen's kappa 和平均绝对分差。
- 若某维度 kappa 小于 0.60 或平均绝对分差大于 1.0，该维度标记为“审核一致性不足”，
  人工均分只能作为探索性结果，不能作为强结论。
- “存在另一种合理打法”不自动算错；事实错误、输入不支持的断言和内部矛盾必须可举证。

## 11. Judge 与人工结果的关系

LLM Judge 用于全量、低成本地发现候选错误，人工盲审用于校准 Judge，不把任何一方
当作绝对真值。正式报告应比较：

- 各维度平均分差。
- 明确事实错误和严重因果错误的检出一致性。
- Judge 是否系统性偏爱更长、更流畅或更自信的回答。

若 Judge 与人工分歧明显，优先检查原文证据、输入和版本条件；不能为了保留漂亮分数
而静默选择其中一方。
